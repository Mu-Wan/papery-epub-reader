# Papery 数据备份格式

## 兼容性约定

Windows 与 Android 共用 `papery-backup` JSON 格式。应用版本与备份格式版本独立；当前格式版本固定为 `1`。书籍原文件使用带 MIME 类型的 Base64 Data URL，不保存平台路径。

版本 1 的既有字段保持含义和读取方式。新增字段应为可选字段，读取时允许未知附加字段。若未来确需改变字段含义或编码方式，须增加格式版本和迁移器，并继续保留版本 1 的导入能力。未知格式版本应在写入前拒绝，提示升级应用。

## 数据范围

| 字段 | 内容 | 记录标识 |
| --- | --- | --- |
| `books` | 原文件、封面、书名、作者、分类、阅读进度和位置 | `id` |
| `annotations` | 划线、高亮、笔记、书签和定位信息 | `id` |
| `settings` | 个人资料、各书排版和最近阅读书籍 | `key` |
| `categories` | 分类名称和修改时间 | `name` |
| `sessions` | 阅读时间记录 | `id` |
| `tombstones` | 已删除书籍、笔记和分类的时间 | `集合:标识` |

Google 客户端 ID、授权令牌、连接状态、设备标识及派生缓存不导出，也不从历史备份导入。原设备的连接配置继续保留在本机。历史版本 1 备份中的缓存和连接设置会被忽略；缺少删除记录的历史备份仍可读取。

## 还原规则

导入前校验格式、记录标识、数据类型、时间及原文件编码。校验与文件解码全部完成后，五个数据集合在同一个数据库事务中写入；异常中止时回滚。

同一标识按修改时间合并，较旧备份不能覆盖较新位置，包括主动向前返回阅读的进度。删除记录按最新时间合并，旧书籍和笔记不会因还原复活。设备标识不迁移；还原成功后移除相应书籍的旧崩溃恢复位置缓存。

## 发布检查

每次修改存储、备份、阅读位置或同步相关代码，均需保留版本 1 样本并核查：三种原文件的字节一致性、封面和头像、分类、排版、笔记与书签、阅读记录、删除合并、双向往返、损坏文件回滚、未知版本拒绝及凭据排除。原生设备的文件选择和写入流程另行检查。

当前检查覆盖桌面和 Android 用户代理的独立浏览器环境，并在 Android 模拟器安装版中实际完成系统文件选择、备份还原和导出，核对三种原文件及全部可迁移数据。Windows 运行实例已核查还原；原生保存对话框按要求交由手动验证。模拟器检查不替代实体手机验收。未来兼容性依靠以上格式约定与持续回归落实，无法预先证明尚未实现的所有版本。
